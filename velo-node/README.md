# velo-node

Адаптер между датчиками каденса Wahoo RPM (BLE, профиль CSC) и игрой `velo-game`:
читает обороты педалей двух велотренажёров, считает скорость и дистанцию,
рассылает телеметрию по WebSocket.

## Запуск

```sh
npm install
cp .env.example .env
npm run dev          # с автоперезапуском
npm start            # обычный запуск
npm run typecheck
```

TypeScript исполняется Node напрямую (нативное срезание типов, Node ≥ 24), сборка не нужна.

### Источник данных

Выбирается переменной `SOURCE`:

| `SOURCE` | Что делает | Что нужно |
| --- | --- | --- |
| `ble` | датчики Wahoo RPM по Bluetooth | встроенный адаптер |
| `ant` | те же датчики по ANT+ | USB-свисток ANT USB-m или Garmin USB2 |
| `mock` | симулятор двух велосипедистов | ничего, для разработки фронта |

```sh
SOURCE=mock npm start
```

Нативные модули загружаются динамически, поэтому в режиме `mock` ни Bluetooth, ни USB
не трогаются вообще.

**BLE** — соединение точка-точка: датчик держит только одно подключение, поэтому
отвяжите его в приложении на телефоне, иначе адаптер его не увидит. Адаптер сканирует
устройства с сервисом CSC (`0x1816`) и подключает не больше двух. На macOS вместо
MAC-адреса используется системный UUID устройства, и нужно один раз разрешить
терминалу доступ к Bluetooth (Настройки → Конфиденциальность → Bluetooth).

**ANT+** — broadcast: соединения нет, один канал сканера принимает сразу все датчики
каденса поблизости, и датчик может одновременно слушать кто угодно ещё. Свисток
определяется автоматически (сначала пробуется ANT USB-m, затем Garmin USB2). Обратная
сторона broadcast — статус «потерян» здесь означает «10 секунд не было новых оборотов»,
потому что уснувший датчик от выключенного ничем не отличается.

### Привязка датчиков к игрокам

Идентификаторы всех найденных, но не подошедших датчиков печатаются в лог —
скопируйте нужный в `P1_SENSOR` / `P2_SENSOR` (для `ble` это BLE id, MAC-адрес или имя,
для `ant` — ANT+ Device ID). Если переменные пустые, датчики привязываются
автоматически в порядке обнаружения.

### Откуда берётся скорость

Wahoo RPM — датчик **каденса**, скорости в нём нет. Она считается по модели
виртуальной передачи:

```
скорость (км/ч) = каденс (об/мин) × WHEEL_CIRCUMFERENCE_M × GEAR_RATIO × 60 / 1000
```

При значениях по умолчанию (2.096 м, 3.0) один оборот педалей ≈ 6.29 м, то есть
80 об/мин ≈ 30 км/ч. Подкрутите `GEAR_RATIO`, чтобы задать «сложность» игры.

Каденс сглаживается экспоненциально (`SMOOTHING_TAU_MS`), а если новых оборотов нет
дольше `SENSOR_TIMEOUT_MS`, он плавно уходит в ноль — велосипедист во фронте
останавливается без рывков.

## Протокол

Сервер → клиент (типы — в `src/types.ts`, раздел «Контракт с velo-game»):

- `hello` — при подключении: версия протокола, частота тиков, метры за оборот, состояние игроков и привязанных датчиков;
- `telemetry` — снапшот `TICK_HZ` раз в секунду: `cadence` (об/мин), `speed` (км/ч), `distance` (м), `connected`;
- `sensor` — датчик привязан или потерян.

Клиент → сервер:

- `reset` — обнулить обороты и дистанцию перед новой гонкой.

Фронт использует копию этого раздела в `velo-game/src/net/protocol.ts` — при изменении
протокола правьте оба файла.

## Архитектура

```
sources/ble.ts   ─┐
sources/ant.ts   ─┼─→ hub.ts ─────────→ transport/ws.ts ─→ velo-game
sources/mock.ts  ─┘   привязка датчиков,  рассылка
                      тик, снапшоты      снапшотов
                        ↑
                  domain/ride.ts — скорость, дистанция, сглаживание
```

Все типы лежат в одном файле `src/types.ts`: контракт с фронтом, конфигурация,
порт источника и доменные структуры.

Источники реализуют один порт `CadenceSource` и отдают уже посчитанный каденс,
поэтому ядро не знает, пришли данные по BLE, по ANT+ или из симулятора. Расчёт
каденса из оборотов общий (`domain/cadence.ts`): BLE-профиль CSC и ANT+ передают
одинаковые поля — накопительные обороты и время последнего оборота в тиках 1/1024 с.

Игровая логика (старт, финиш, победитель) находится во фронте — адаптер отдаёт
только телеметрию.
